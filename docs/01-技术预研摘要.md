## 1. 结论速览

| # | 结论 | 依据 |
|---|---|---|
| 1 | .com 与 .red 是**同一套后端/同一数据库的两种过滤视图**，REST API 完全相同，下载器无需写两套逻辑 | 【文档】[官方公告](https://civitai.com/articles/28369/two-front-doors-civitaicom-civitaired-and-whats-next) ｜【实测】两站同请求返回内容一致（同图片、同 meta、同 CDN） |
| 2 | 采集应走**官方 REST API `/api/v1/images?withMeta=true`**，匿名即可拿到含 NSFW 的完整 prompt/参数，不强制 API Key | 【文档】[images.md](https://developer.civitai.com/site/reference/images.md) ｜【实测】匿名 X 级图片返回完整 prompt+negativePrompt |
| 3 | 网页 HTML 解析**不适合做 MVP 主路径**：.com 页面会触发 Cloudflare 人机校验，且图片页数据在 tRPC 里 | 【实测】抓文章页返回 403 `Just a moment...` ｜【第三方】[gallery-dl](https://github.com/mikf/gallery-dl/blob/master/gallery_dl/extractor/civitai.py) |
| 4 | 分页是**最大硬约束**：`page*limit>1000` 直接 429，全量必须用 cursor 走 `metadata.nextCursor` | 【文档】[pagination.md](https://developer.civitai.com/site/guide/pagination.md) ｜【实测】`page=11&limit=100` → 429 |
| 5 | 官方**不公开稳定速率契约**，只有 Cloudflare 边缘限流；工程上按保守节流 + 尊重 `Retry-After` 设计 | 【文档】[errors.md](https://developer.civitai.com/site/guide/errors.md) ｜【第三方】[comfyui-lora-manager](https://github.com/willmiao/comfyui-lora-manager/blob/104d2675ae9817649196d8c797afe5df3c1f9a3a/docs/plans/issue-1085-rate-limit-design.md) |
| 6 | 真正的不确定性在**元数据质量**：meta 由上传工具自由写入、常缺失、结构不统一，是产品体验与问卷的重点 | 【文档】images.md ｜【实测】A1111/ComfyUI/SD.Next/Krea 四种 meta 结构并存 |

## 2. 问题一：civitai.com 与 civitai.red 的关系

| 维度 | 结论 | 依据 |
|---|---|---|
| 定位 | 2026-04-15 起 .com = SFW 前门（原 civitai.green），.red = 自由优先前门（原 civitai.com 全量内容）；civitai.green 301→civitai.com | 【文档】[Two Front Doors](https://civitai.com/articles/28369/two-front-doors-civitaicom-civitaired-and-whats-next)、[Goodbye blue](https://civitai.com/articles/28676/goodbye-blue-hello-red) |
| 后端 | 官方 FAQ：“两个域名是**同一数据库上的过滤视图**”，账号/Buzz/模型/图片/关注不迁移 | 【文档】同上 |
| 内容差异 | .com 站内 UI 锁 PG；.red 可自选浏览级别；NSFW 只在 .red 展示 | 【文档】同上 |
| API 差异 | 官方 FAQ：“**REST API 不变**，仍挂在 civitai.com，也可从 civitai.red 访问，现有集成无需改动” | 【文档】同上 |
| 登录态 | 一个账号通用于两站；【第三方】civitai-grabber：“两站登录可互换，任一站登录对两站链接都有效” | 【文档】同上 ｜【第三方】[README](https://github.com/Overbooster/civitai-grabber) |
| 实测 | `GET /api/v1/images` 在 .com 与 .red 返回**完全相同**的条目与 CDN 地址；.com 也能匿名查到 `nsfwLevel:X` 条目 | 【实测】同一请求两域对比 |
| 注意 | cookie 域不同（`.civitai.com` vs `.civitai.red`），浏览器登录态需按域名分别保存；部分国家因合规（如英国 OSA）被整体地理封锁，与 NSFW 无关 | 【文档】公告 ｜【第三方】gallery-dl 用 `__Secure-civitai-token` |

## 3. 问题二：提示词与生成参数的数据来源

| 来源 | 能拿到什么 | 依据 |
|---|---|---|
| `GET /api/v1/images`（需 `withMeta=true`） | id、url、hash(BlurHash)、宽高、type、`nsfwLevel`(字符串)、`browsingLevel`(位掩码)、createdAt、postId、username、baseModel、`modelVersionIds`、stats、**meta** | 【文档】[images.md](https://developer.civitai.com/site/reference/images.md) |
| meta 内 | prompt、negativePrompt、sampler、steps、cfgScale（部分工具写 `cfg`）、seed、Size/宽高、clipSkip、`resources[]`（名称+hash+权重）、`civitaiResources[]`（type + modelVersionId + weight） | 【文档】同上 ｜【实测】 |
| `GET /api/v1/models` | 模型名/类型/NSFW 标记/tags/creator/stats、`modelVersions[]`（id、baseModel、files[] 含 hashes、downloadUrl）；`version.images[]` 只有 id/url/nsfwLevel 与 `hasMeta`、`hasPositivePrompt` 标志，**不含 prompt** | 【文档】[models.md](https://developer.civitai.com/site/reference/models.md) |
| `GET /api/v1/model-versions/{id}`、`/mini/{id}`、`/by-hash/{hash}` | AIR、trainedWords、files/hashes/downloadUrl、预览图；by-hash 可用本地文件反查模型版本 | 【文档】[model-versions.md](https://developer.civitai.com/site/reference/model-versions.md) |
| `GET /api/v1/posts/{id}` | 帖子标题/描述/标签/图片列表，但 `images[].meta` **恒为 null**；要 prompt 必须再调 `/images?postId=&withMeta=true` | 【文档】[posts.md](https://developer.civitai.com/site/reference/posts.md) |
| 网页端 | 【第三方】gallery-dl 默认走 tRPC：`/api/trpc/image.getInfinite`、`image.getGenerationData`（单图生成数据）、`model.getAll`、`post.get` 等，需 `x-client`、`x-client-version`、`x-client-date` 头，`input={"json":{...},"meta":{"values":{...}}}` | 【第三方】gallery-dl 源码 |
| 网页端（2） | 【第三方】civitai-grabber 明确写：“**图片页面无法被脚本直接读取**，部分元数据与画廊图只能借助浏览器会话”，故其内置浏览器扩展桥；【推测】`__NEXT_DATA__` 已非主路径，数据主要走 tRPC | 【第三方】README ｜【推测】 |

- 无 API Key 能否拿 prompt：**【实测】可以**。匿名 `GET /api/v1/images?nsfw=X&limit=3&withMeta=true` 直接返回 X 级图片的完整 prompt 与 negativePrompt。
- meta 的实际形态（均见【实测】HTTP 200 响应）：A1111 风格（`Size`/`Model`/`Hires steps`/`Denoising strength`/`ENSD`）；ComfyUI 风格（`comfy`、`workflow` 整段 JSON、`engine`、`models`、`scheduler`）；SD.Next（`App`/`Pipeline`/`Mask *`）；站内 Krea 生态（`ecosystem`/`resolution`/`aspectRatio`/`Created Date`/`civitaiResources`）。`negativePrompt` 在 Krea/ComfyUI 类数据中**常常不存在**。
- 【文档】meta 是自由格式对象，“未知 key 当不透明处理”；只有作者发布时带元数据才有 meta，否则为 `null` → 对应问卷 Q2.4「没有提示词的图怎么处理」。

## 4. 问题三：认证、NSFW 门槛与限流

| 项 | 结论 | 依据 |
|---|---|---|
| API Key | 可选。端点分 public / mixed / authenticated；`/images`、`/models/{id}`、`/model-versions/*` 属 public，匿名可用 | 【文档】[authentication.md](https://developer.civitai.com/site/guide/authentication.md) |
| 凭证方式 | 账号设置生成 bearer token（`Authorization: Bearer`，也支持 `?token=`）；面向第三方分发建议 OAuth（用户显式授权、可撤销） | 【文档】同上 |
| NSFW 读取 | 匿名按“public browsing level”返回；【实测】匿名即可列 Mature/X 条目及其 prompt，**无需登录或 Key** | 【文档】images.md ｜【实测】 |
| NSFW 生成/下载 | 需登录、Buzz 与会员权限（与“读元数据”是两回事） | 【文档】公告 ｜【推测】按 Buzz 条款推断 |
| 限流 | **无公开稳定数值**；Cloudflare 在 API 前做边缘限流，“运营性、非 SLA”；429 = 边缘限流或分页上限，403 = 有 token 但无权限，401 = 未授权 | 【文档】[errors.md](https://developer.civitai.com/site/guide/errors.md) |
| 重试 | 5xx/429 指数退避（1s→上限约 30s）；多数错误不带 `Retry-After`，但 `/posts` 与部分场景带；429 时须读 `Retry-After` | 【文档】errors.md、posts.md |
| 反爬 | 【实测】直接抓 `civitai.com/articles/...` HTML 返回 **403 `Just a moment...`**（Cloudflare 挑战）；同日 API 端点未被拦。HTML 页面不可靠，API 相对稳定 | 【实测】 |
| 社区经验 | 【第三方】comfyui-lora-manager：CivitAI 匿名/带 Key/是否 .red 的差异“未验证”，取 `0.75s/请求（≈80 rpm）` 作保守节流，单次 429 等待上限 300s；CivArchive 曾出现 ~1500s 的 Retry-After | 【第三方】[rate-limit 设计文档](https://github.com/willmiao/comfyui-lora-manager/blob/104d2675ae9817649196d8c797afe5df3c1f9a3a/docs/plans/issue-1085-rate-limit-design.md) |

## 5. 问题四：可行的采集入口

| 入口 | 对应 API / 参数 | 备注 |
|---|---|---|
| 关键词搜索（模型） | `GET /api/v1/models?query=<text>&limit=&cursor=` | Meilisearch 全文；`query` **必须**配 cursor，配 `page` 会 400 【文档】 |
| 关键词搜索（图片） | REST `/images` **没有** query 参数；【第三方】gallery-dl 走 `https://search-new.civitai.com/multi-search`（索引 `images_v6`/`models_v9`，用硬编码公开 bearer key） | 该 key 可能失效，不宜硬编码；【推测】可由登录态页面抓取替代 |
| 按模型 / 版本 | `/models?ids=`、`/models/{id}`、`/images?modelId=`、`/images?modelVersionId=` | 大模型用 `modelId` 排序易超 Cloudflare 30s 超时，官方建议改 `postId` 或 cursor 【文档】 |
| 按作者 | `/images?username=`、`/images?userId=`、`/models?username=` | username 自动 slug 化 【文档】 |
| 按标签 | `/models?tag=`；`/images?tags=<id,id>`（多个 = **AND**） | 【文档】 |
| 榜单 / 排序 | `/images?sort=Most Reactions|Most Comments|Most Collected|Newest|Oldest|Random&period=Day…AllTime`；`/models?sort=Most Downloaded|Highest Rated|…` | 【文档】 |
| 单图 URL | 解析 `/images/{id}` → `/api/v1/images?imageId={id}&withMeta=true` | 【实测】SFW 图可用；**匿名查成熟图返回空 items** |
| 单帖 URL | `/api/v1/posts/{id}` + `/images?postId={id}&withMeta=true` | 【实测】匿名查成熟帖的 images 为空 |
| 翻页 | 统一用 `metadata.nextCursor`（或直接跟随 `metadata.nextPage`） | page*limit≤1000 【文档】 |
| 已有开源可参考 | [civitai-grabber](https://github.com/Overbooster/civitai-grabber)（Windows/Python，模型+示例图+prompt 写 dscr.txt，带浏览器扩展）、[Civitai_API_Downloader](https://github.com/EricRollei/Civitai_API_Downloader)、[civitdl](https://pypi.org/project/civitdl/)、gallery-dl | 【第三方】 |

## 6. 问题五：主要坑清单

| # | 坑 | 表现 / 应对 | 依据 |
|---|---|---|---|
| 1 | 分页硬上限 | `page*limit>1000` → 429 `You've requested too many pages, please use cursors instead`；UI 的“第 N 页”不能直接映射，全量必须 cursor | 【文档】+【实测】 |
| 2 | `/images` 的 `page` 基本无效 | 只对 `imageId`、或 `modelId`（无 modelVersionId）生效，其余请求被忽略并返回第一页；误用会死循环 | 【文档】images.md |
| 3 | 空页 ≠ 结束 | 空 `items` 仍可能带 `nextCursor`，只有 `nextCursor` 缺失才终止 | 【文档】images.md |
| 4 | cursor 与过滤条件绑定 | 中途换过滤条件 → 400 `This cursor cannot be continued with these filters`；503 需带同一 cursor 重试 | 【文档】images.md |
| 5 | 字段缺失/自由格式 | `meta` 可为 null；`negativePrompt` 常缺；A1111/ComfyUI/SD.Next 键名不同；`meta` 里 ComfyUI 整包可达数十 KB → 导出需原样保留 + 解析层容错 | 【文档】+【实测】 |
| 6 | 同一接口两种形状 | 【实测】列表接口 `meta` 是平铺对象；`imageId` 单图接口返回 `meta:{id, meta:{...}}` 双层 → 解析要兼容 | 【实测】 |
| 7 | 单图/单帖查询被过滤 | 【实测】匿名用 `imageId=`/`postId=` 查成熟内容返回空 `items`（可能是未完成审核扫描或浏览级过滤）→ 需登录态，或改走列表 + 本地索引 | 【实测】 |
| 8 | 图片 CDN | 【实测】`image.civitai.com/...` 302 跳 `blobs-b2.civitai.com`（Backblaze B2），URL 无签名、未观察到 Referer 防盗链；下载器须跟随 302、支持重试/断点；`width=` 可降采样，`original=true` 才是原图 | 【实测】+【推测】 |
| 9 | 域名差异 | API 无差异（两站等价）；差异在网页 UI 与 cookie 域；不要为 .red 复制一套解析逻辑 | 【文档】+【实测】 |
| 10 | 反爬 | HTML 页面 403 Cloudflare 挑战；tRPC 需 `x-client-*` 指纹头，随前端版本漂移（风险高） | 【实测】+【第三方】 |
| 11 | 地区与年龄 | 部分国家整体封锁；ToS 要求 18+；商用/再分发需注意 ToS 6.1「个人非商业许可」、6.2「不得绕过访问控制」 | 【文档】[TOS](https://civitai.com/content/tos)、公告 |

## 7. 问题六：MVP 技术路线结论

**结论：官方 REST API 优先，tRPC 兜底，网页 HTML 解析不进 MVP。**

| 阶段 | 范围 | 技术要点 |
|---|---|---|
| MVP-1（匿名，必做） | 关键词/模型/作者/标签/榜单圈定 → cursor 全量遍历 → `withMeta=true` 导出 CSV/JSON（含 prompt、negative、sampler/steps/cfg/seed/size、LoRA 列表、作者、tags、NSFW 分级、URL） | 单线程 + 0.7–1s 间隔 + 429/503 指数退避；`withMeta` 必带；原图/缩略图可选 |
| MVP-2（登录态增强） | API Key / OAuth 由用户在界面填入、本地加密保存；解锁高分浏览级、单图/单帖直查、私有与 early-access 内容 | 授权走 [authentication.md](https://developer.civitai.com/site/guide/authentication.md)；面向客户分发优先 OAuth |
| MVP-3（可选） | 浏览器扩展桥或 tRPC 补画廊图/特殊字段；.red 域 cookie 单独保存 | 仅在客户强需求时做，维护成本高 |

**风险清单**

| 风险 | 等级 | 影响 | 应对 |
|---|---|---|---|
| 限流策略不公开、可能随时收紧（Cloudflare/匿名 IP 封禁） | 高 | 批量任务中断、429/403 | 保守节流、可配置并发、断点续传、失败重试队列、提示用户自备 API Key |
| NSFW 单图/单帖匿名查询受限 + 地区封锁 | 高 | 客户核心诉求（NSFW prompt）可能拿不全 | 强制/引导登录态；列表式抓取替代单条查询；问卷确认目标地区与内容级别 |
| 字段缺失（无 meta / 无 negativePrompt） | 高 | 数据完整度不可承诺 | 交付“原始 JSON + 解析列”，问卷 Q2.4/Q2.5 明确策略 |
| 网页端/前端指纹漂移 | 中 | tRPC 兜底方案随时失效 | 不进入主路径，接口版本化隔离 |
| 合规与版权 | 中 | 商用/再分发风险 | 问卷 Q1.4 确认用途；默认按个人使用设计，加免责声明与速率限制 |
| 分页语义变更（feed: cursor 灰度中） | 中 | 抓取逻辑需兼容旧 cursor | 只透传 `nextCursor`，不解析、不自造 cursor |
| 图片 CDN URL 形态变更 | 低 | 下载 404/302 失败 | 以 API 返回的 `url` 为准，跟随重定向 |

**待客户问卷确认的 6 个关键点**：Q1.2 量级与频次（决定节流与断点设计）；Q1.4 用途性质（决定合规边界）；Q2.1/Q2.2 字段范围；Q2.3 是否下载图片文件（决定存储与限流压力）；Q3.1 圈定入口（MVP 只做 2–3 种）；是否接受“用户自备 API Key / 登录”以换取 NSFW 与更高稳定性。

**参考**：官方文档索引 <https://developer.civitai.com/llms.txt>；站点 API 总览 <https://developer.civitai.com/site.md>；Civitai 开源仓库 <https://github.com/civitai/civitai>。
